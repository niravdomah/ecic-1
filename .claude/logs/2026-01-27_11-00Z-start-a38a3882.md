## What would need to change

1. **Implement the `post_tool_use` handler** to write tool name, input summary, and result to the session log file (same pattern as the subagent handlers)
2. **Truncate large results** - tool results like `Read` or `Grep` can return thousands of lines. You'd need truncation similar to the 300-char subagent truncation.
3. **Coordinate with the `response` handler** - currently the `Stop` hook batches all assistant turns at the end. If `post_tool_use` is also logging in real-time, you'd either:
   - Remove the batched `response` handler entirely (since real-time covers it)
   - Or have the `response` handler skip turns already logged, which is more complex

## Key trade-off to consider

`PostToolUse` fires for **every** tool call - `Read`, `Grep`, `Glob`, `Bash`, `Edit`, `Write`, `Task`, `TodoWrite`, `AskUserQuestion`, etc. In this session alone, that's dozens of invocations. Each one spawns a PowerShell process, reads the session file, and appends to it. This means:

- **More granular, real-time logging** (which is what you want)
- **More log file I/O and process overhead** (a PowerShell process per tool call)
- **Much larger log files** (tool results can be verbose)

You could mitigate verbosity by filtering which tools to log (e.g., only `Bash`, `Edit`, `Write` results, not `Read` or `Grep`) or by aggressive truncation.
